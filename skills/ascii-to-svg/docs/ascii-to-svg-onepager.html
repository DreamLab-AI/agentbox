The problem

A diagram is only as trustworthy as it is current.

Hand-drawn ASCII diagrams are honest. They live in the file, they show up in diffs, and an agent reading your repo can parse them. But they look like what they are — characters in a box.

A pasted image looks polished, right up until someone changes the architecture and forgets the picture. Now the diagram says one thing and the code does another, and every reader has to guess which one to trust. That gap is the thing we set out to close.

Trust gets spent

How the two stay honest

One source of truth. One beautiful rendering. A hash that binds them.

01

ASCII is the source

You write the diagram in plain characters, kept in a collapsible block right under the image. It is diffable, reviewable, and machine-readable — the version of record.

02

SVG is the rendering

We convert each diagram into a clean, validated SVG and reference it as the visible image. That is what your readers actually see — designed, not drawn.

03

A manifest binds them

Every diagram's ASCII is hashed and tracked. Edit the ASCII, the hash changes, the SVG is flagged stale and regenerated. The picture is never allowed to outlive its source.

Get started

Drop it in, then forget it.

Install once, add one rule, and diagrams render themselves as part of the work — no separate step to remember.

1 · Install the skill

Copy the folder into your Claude Code skills directory.

# available in every project
cp -r ascii-to-svg ~/.claude/skills/

2 · Make it automatic

Add this to your project's CLAUDE.md so SVGs are created proactively.
