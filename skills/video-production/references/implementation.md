# Implementation plan and code/check backlog

Design IDs: PRD-VIDEO-001, ADR-2150 (`docs/adr/ADR-2150-video-production-skill.md`) and DDD-VIDEO-001. This is a proposed extraction and implementation plan. The named Rust modules, traits and methods below are target interfaces, not existing public APIs or runnable commands. [Contracts](contracts.json) and [DDD](ddd.md) govern domain names and versioning; reconcile this plan with them before implementation.

## Runtime shape

Start with one Rust library/application process, not independently deployed microservices. Use modules for bounded contexts and thin application adapters for external tools. Native files remain native: manifests reference assets by logical ID, URI and content hash rather than reproduce Blender meshes or solver databases. Keep Python around `bpy`, solver bindings, speech recognisers and image libraries where it is thin integration.

The following signatures are interface specifications. `Result` means a typed domain error, including invalid/stale input, unsupported capability, unavailable provider, resource limit and ambiguous submission. Persist successful state before emitting its event. All output-writing APIs accept a new destination or an explicit revision; they must not silently overwrite verified evidence.

Implement provider interfaces with synchronous or asynchronous methods as the runtime warrants; the semantic contract is mandatory, a particular Rust async trait framework is not. Separate native rendering, generation, speech and physical capabilities rather than requiring every adapter to fake every operation. Cancellation support is an explicit capability. Use standard cryptographic crates for hashes; do not introduce custom cryptography.

### Native dependency closure

Hashing a `.blend` or scene manifest alone cannot establish reproducibility. `resolve_native_dependencies` must enumerate linked libraries and their transitive links, unpacked textures/UDIM tiles/image sequences, fonts, geometry/volume/simulation caches, external audio, referenced scripts and other result-affecting files. Bind each logical dependency to its resolved location, content digest and role; hash actual symlink targets rather than only link text. Record result-affecting application/add-on/interpreter versions, render configuration, environment settings and seeds separately in the environment fingerprint. File hashes cannot certify hidden application state or uncontrolled randomness.

The adapter declares which dependency classes it can enumerate. Unresolved, missing or dynamically generated dependencies make closure incomplete; that blocks a reproducible/reusable render claim until explicitly captured or isolated. It must not silently claim that a top-level file hash covers them. Stage a verified immutable dependency set, or enforce equivalent read isolation and record the exact dependency bytes consumed. Preflight revalidation alone leaves a validation-to-read race and is insufficient. Reuse proofs bind that consumed closure. Handle cyclic library references with visited identities; cycles must not hide missing dependencies. A changed linked texture or font invalidates every dependent render even when the `.blend` bytes are unchanged.

### Cancellation and duration boundaries

Cancellation is job-scoped by owned job ID, or it is reported unsupported. Never issue a provider-global interrupt on a shared instance: a queue snapshot, a local mutex used only by this client, or a check immediately before the interrupt does not close the race with another producer. When the provider offers no scoped operation, declare cancellation unsupported and stop local scheduling and observation as requested without claiming the remote job stopped. Preserve `cancellation-requested`, completed, cancelled and unknown as truthful provider outcomes; quarantine late or intermediate outputs from cancelled or superseded attempts rather than auto-promote them.

`DurationPolicy` declares whether frame count or nominal seconds is authoritative, the allowed rounding mode, and the maximum duration error. At 30000/1001 fps an exact 18 seconds is not an integral constant-rate frame count: 539 frames last 17.984633… seconds; 540 frames last 18.018 seconds. Reject conflicting exact constraints. For permitted rounding, record requested/represented duration, signed error and selected frame count before work begins. Padding cannot change delivery duration. Derive sample/frame conversions from absolute rational positions with declared rounding, not accumulated rounded increments. A changed dialogue duration requires a new explicit editorial policy/revision; fixed-window replacement cannot silently stretch the take or the edit.

## Pending semantics to resolve before code locks

- Define canonical digest input bytes and schema migration policy; JSON formatting must not silently alter semantic revision identity.
- Encode the declared sample/frame rounding, duration precedence/error policy and unsupported model rates in the versioned contracts. Preserve native and delivery clocks rather than relabel frames.
- Define complete render/reuse fingerprints and dependency-closure manifests: transforms alone omit deformed geometry, materials, visibility, camera settings, effects and external files. Scope proofs must state their coverage.
- Define output ownership and lock/recovery storage; cancellation stays job-scoped. Ambiguous provider submission cannot be solved by an optimistic retry; reconciliation may need operator-visible manual resolution.
- Define actor assembly/ownership IDs independently of scene-object names and mask palettes. Tracking association is reviewed identity evidence, not automatic truth.
- Define exactly which physical telemetry each adapter can provide and the scope of a verified solve. Do not mark whole-scene collision verified from a local cable probe.
- Define audio replacement policy for duration changes, crossfades and adjacent review intervals. Fixed-window replacement and editorial retiming are separate operations.
- Define independence/degraded-review fields and acceptance scope; no proposed ADR should carry a fabricated `verified_commit`.

Resolve these as versioned contract/ADR updates with negative fixtures, not permissive defaults that allow claims beyond evidence.
