# Architecture decision worksheet

Use the repository's ADR format if present. This worksheet is documentation,
not an automatic ratification or staleness mechanism.

## Identity and status

Record the decision ID, title, date, owner/authority and actual status. New
proposals remain proposed until accepted under the project's process. Link
dependencies, amendments and superseded decisions.

## Context and alternatives

Describe the behaviour or constraint requiring a choice, known observations,
credible alternatives and the tradeoff that matters. Separate facts from
assumptions and identify uncertainty that could change the decision.

## Decision and consequences

State the chosen boundary, consumer responsibilities, expected costs, risks and
reversal/migration path. Explain how the choice will be tested or reconsidered.

## Source verification

For implemented claims, record the inspected full commit and nonempty governed
paths plus relevant dependencies/configuration. Link actual checks. For an
unimplemented proposal, leave implementation verification explicitly absent.
Commit the code before stamping its revision. A later changed path creates a
review obligation, not automatic proof that this decision is wrong.
