# Agentbox System Audit — 2026-07-15 (Opus mesh)

Fable-queen + 6 Opus auditors, one per subsystem. Seeded by the discovery that the
`blender`/`qgis` skills were invisible to every session. The audit found that gap is
**one instance of a repo-wide pattern**: agent-facing state (skills, MCP servers) is
hand-accreted onto persistent volumes with no deterministic builder mechanism, so it
drifts, goes stale, and diverges by launch directory.

Severity: **P0** breaks things · **P1** wrong-but-survivable · **P2** hygiene.
Each finding is evidence-backed (file:line) in the per-dimension registers under
`scratchpad/audit/findings-*.md`. This is the reconciled master ledger.

## The through-line

Three subsystems share the identical failure mode — *"a template/source of truth exists,
but nothing at build/boot projects it deterministically into the place the runtime reads;
instead it's hand-copied and persists on a volume, so it drifts and never heals"*:

- **Skills**: source `skills/` → baked `/opt/agentbox/skills` (115, faithful) → but
  `~/.claude/skills` (what the Skill tool reads) is hand-accreted (17), and there are
  **four divergent skill roots** that don't agree.
- **MCP**: `skills/mcp.json` (28-server registry) has **no runtime consumer**; the
  entrypoint hand-maintains a divergent 7-server allowlist. Same rot, at scale.
- **Config**: `.mcp.json` reconciliation is **add-only** against a persisted volume file,
  so gated-off / dead entries never get removed.

Fixing the *mechanism* (deterministic, gated, reconcile-not-append projection from a
single source of truth) fixes all three classes at once. The skill-registration
re-engineering already landed this turn (`skills/registered-skills.txt` +
`scripts/reconcile-skills.sh` + entrypoint boot reconcile) is the first instance.

## Dimension 6 — sidecar + GPU (7 findings, 3 P1 · runtime-verified)

> The detailed register file did not persist; this is reconciled from the auditor's
> completion report. All P1s were runtime-verified.

- **GPU-1 [P1] — the nix GPU bug is systemic, not Blender-specific.** nvidia driver libs
  inject FHS-style into `/usr/lib`, but `/usr/lib` is **not on the global `LD_LIBRARY_PATH`**,
  so *every* nix GPU binary silently CPU-falls-back — only Blender got a per-tool wrapper
  (`blender-batch.sh`). **Confirmed by runtime test: `ffmpeg h264_nvenc` encodes 0 frames
  (error -22) without the fix, succeeds with `LD_LIBRARY_PATH=/usr/lib`.** The `ffmpeg`,
  `imagemagick`, and any other nix GPU tool are affected. Direction: a global/curated
  `LD_LIBRARY_PATH` append (weigh ABI risk of shadowing nix libs) or per-tool wrappers like
  Blender's — an operator decision.
- **GPU-2 [P1] — in-container Vulkan is entirely dead.** `VK_ICD_FILENAMES` points at a
  nonexistent `/run/opengl-driver` path → no Vulkan in agentbox-main. This is the *root cause*
  that forced the Blender → GPU-sidecar migration; worth fixing so future GPU tools have a
  local Vulkan option.
- **GPU-3 [P1] — no durable GPU-assignment source of truth.** ARC-002 is consistent in source
  but diverges at runtime: `gui-tools` grabbed all 3 GPUs while `browsercontainer` + `xr-runtime`
  both silently pin the **same** GPU2. `device_ids: ['all']` is non-idiomatic and only works via
  the env belt-and-braces. Direction: a per-sidecar GPU pin from one manifest source.
- **GPU-4/5/7 [P2] — resolved briefing hypotheses:** `NVIDIA_VISIBLE_DEVICES=void` is **NOT a
  bug** — it's the nvidia-container-toolkit *post-injection sentinel*; `Config.Env=all` and
  nvidia-smi sees all 3 GPUs (benign, undocumented — **this corrects the earlier "void = latent
  misconfig" note**). `qgis_mcp_standalone.py` is a misleadingly-*named* proxy (hygiene), not a
  break — the proxy pattern (blender + qgis) is consistent and working.

## Correction to earlier notes

`NVIDIA_VISIBLE_DEVICES=void` was flagged as a suspected misconfiguration during the seed
investigation; the sidecar auditor runtime-verified it is the **benign nvidia-container-toolkit
injection sentinel** (Config.Env=all). Not a finding — only the missing documentation is.
